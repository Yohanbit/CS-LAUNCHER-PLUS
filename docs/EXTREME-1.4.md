# Unamed launcher 1.4 EXTREME — experimental Android build

## Install and recovery

Download `Unamed launcher.apk` from the prerelease generated by this branch. The app and prerelease titles use the same new name. Package remains `com.cslaucher.plus.debug` to preserve update compatibility and existing data; project debug signature. ARM64 and ARM32, manifest minimum Android 5.0; individual Java/Minecraft versions can require a newer OS. Back up worlds, profiles and options before updating. A mismatched signature requires a separate install or explicit uninstall after backup; do not erase data to troubleshoot blindly. The repository URL and upstream legal credits are deliberately unchanged.

Start the reported 26.2 instance without mods first, then Fabric, then Sodium. The supplied crash showed MobileGlues/EGL initialization succeeded, followed by `UnsatisfiedLinkError: Failed to locate library: liblwjgl.so`. This branch packages checksum-pinned Android LWJGL 3.3.3/3.4.1 assets and SDL/OpenAL/SPIRV-Cross JNI libraries. CI refuses to publish an APK without these payloads. API/symbol checks are not proof of successful Minecraft execution.

MobileGlues 2.0.0 is bundled; its configuration directory is exported before loading. Installing a separate renderer APK is not required for this bundled backend. No credential or Firebase configuration is fabricated. Debug builds use the existing explicit no-Firebase development path; Firebase services remain inactive without genuine configuration. Android surface refresh hints use the selected FPS policy rather than a stale pre-launch game cap; explicit launcher Force VSync remains authoritative (off by default).

## Connected functionality

- FPS policy: Unlimited (default), Manual, Original/restore. Pacing-only changes to `options.txt` are backed up and reversible; distances, particles, shaders and world quality are not changed. Unlimited writes the vanilla maximum-slider sentinel `maxFps:260`, disables game VSync and asks the native EGL path for interval 0. This is not a hardcoded native 260 FPS cap. The sentinel's behavior in newer game versions/mods must still be checked on device. No software sleep limiter was found in the native render path; required event handling, teardown synchronization and OSMesa completion remain intact.
- EXTREME uses a compatible renderer recommendation, quiet launcher and ergonomic JVM defaults. It is not a measured universally faster profile. Selecting other profiles/Original permits controlled comparisons. Hardware thermal protections are never disabled.
- Dynamic resolution is opt-in: framebuffer scale adjusts with hysteresis within the user's selected floor and initial scale. It restores the manual scale when disabled/backgrounded. This affects image quality; its target is a control target, not an FPS limiter. It is surface/framebuffer scaling, not Minecraft world-only rendering or frame interpolation.
- Scheduler fixes enforce a session-wide boost cap, conservative game-thread matching, saved-priority restoration and thermal shedding. Android may reject requests. Maximum's ADPF remains target-only, not a demonstrated performance-feedback improvement.
- Renderer tuning is scoped to the actual backend after fallback. MobileGlues receives no unrelated Mesa/Zink/Turnip tuning. Unsupported experimental G1 young-generation flags were removed. Shader caching already existed; no invented duplicate cache is advertised.
- Native diagnostics count successful swap submissions and CPU wall time around swaps, including failures; the counter no longer double-counts JNI/GLFW paths. Optional CSV polling records native/ART memory and Android thermal status. Optional GC logs cover the embedded game JVM separately. These are not GPU timing or proof of compositor presentation, and one-second samples do not provide frame-time percentiles.
- Promotional server injection and automatic welcome/tutorial prompts are removed. Saved user server/world data and legal attribution are preserved. Previously injected game-list entries can be deleted manually; the build does not guess which stored entries the user wants deleted.

## Actual validation and limitations

Host validation: 74 performance-policy/history assertions against Android stubs; native policy/concurrency, ASAN/UBSAN, mocked EGL/OSMesa tests; 47 dynamic-resolution assertions reported by its module tests; 7 reversible option assertions. CI performs the integrated Android Java/native build, APK payload, ELF architecture and signature checks. Results from mocks/stubs do not establish Android runtime behavior.

No access to the user's Mali-G76 exists here. No measured FPS gain, display refresh gain, GPU timing, input latency improvement, Sodium compatibility, temperature result or successful physical installation is claimed. EGL interval 0 is a request: EGL config minimum interval, driver queues, SurfaceFlinger, screen refresh, Minecraft background/menu logic and mods can still constrain output. Verify these rather than treating a counter as displayed FPS.

World-only DRS, GPU timestamp integration and frame interpolation are not implemented: this launcher does not own Minecraft's render graph and no validated cross-version injection is available. Interpolation is not genuine game simulation FPS. Deep renderer/LWJGL allocation changes without measurements were not applied indiscriminately.

## Reproducible A/B on Mali-G76

1. Back up the same instance. Keep version, Java, mods, world, camera route, RAM, resolution, graphics and screen refresh identical. Record device/Android, battery, charging state and room temperature.
2. Baseline A: use original APK with working matching natives, or this APK with Original FPS policy and Normal profile. A crash is not a valid performance baseline.
3. Treatment B: EXTREME/Unlimited at unchanged resolution; DRS off. Warm the same scene for two minutes, record five minutes, cool down, repeat in ABBA order at least twice. Compare scene stability and errors, not only peak FPS.
4. Enable diagnostics identically in both runs. Collect `performance/frames-*.csv`, GC logs and `latestlog`. Record game F3 FPS and frame-time graphs; obtain per-frame/compositor traces through Android Perfetto if available. CSV measures submissions and averaged wall time, not GPU/displayed frames. Compare memory, GC pauses, stutter and thermal trajectory.
5. Test DRS separately with an explicitly chosen floor/target. Note visual quality and scale changes. Test pause/resume, manual FPS/VSync, Original restore, backend fallback and Sodium on/off separately.
6. If launch fails, send the full latest log, device model, selected renderer and exact instance/mod versions. Disable the changed option or restore Original; do not install random JVM flags or disable thermal safeguards.
